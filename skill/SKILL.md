# /monthly — сводка месяца для отчёта в Hive

Собирает из **локальных** транскриптов Claude Code (те же файлы, что ежедневно уходят в `/report`)
один текстовый файл: по дням — проекты и сайты, задачи (запросы пользователя), итог каждой
сессии, инструменты, оценка активного времени. Пользователь сам загружает файл в Hive → «Отчёты»,
и ИИ Hive строит по нему one-pager. Файл никуда не отправляется, секреты вырезаются.

## Шаги (для ассистента)

1. **Спросить месяц.** «За какой месяц собрать отчёт? (Enter = прошлый месяц; или `2026-08`)».
   Дождаться ответа.
2. **Запустить сборку:**
   ```bash
   node ~/.claude/skills/monthly/monthly.mjs --month <YYYY-MM>
   ```
   Скрипт печатает статистику и путь к файлу (по умолчанию
   `~/Documents/Отчёты Hive/Отчёт Claude Code — <месяц> <год>.txt`). Если сессий за месяц нет —
   так и сказать пользователю и остановиться. Если в статистике есть строка «Транскрипты сессий
   на диске — с …» — часть дней собрана только по истории запросов (см. Примечания), сказать об
   этом пользователю в шаге 5 одной фразой.
3. **Прочитать созданный файл целиком** (Read). Он уже структурирован по проектам и дням.
4. **Написать «РЕЗЮМЕ МЕСЯЦА».** Заменить в файле строку-заглушку
   `[РЕЗЮМЕ: заполняется при запуске /monthly — …]` на 8–15 строк-пунктов (Edit):
   - по каждому проекту/сайту: что сделано и чем закончилось (готово / в работе / заблокировано);
   - конкретика: цифры, названия страниц, фич, серий статей, если они есть в задачах и итогах;
   - только то, что есть в файле — ничего не додумывать. Без оценок «отлично», «продуктивно».
   Писать от первого лица, деловым языком, как сотрудник пишет руководителю.
5. **Показать пользователю** резюме целиком и статистику (дни, сессии, часы, проекты), напомнить
   путь к .txt и к архиву «Сессии Claude Code — <месяц>.zip» (скрипт печатает оба) и что дальше:
   > 1) Проверьте текст, при желании поправьте файл. Затем Hive → «Отчёты» → загрузите этот .txt,
   > ИИ Hive соберёт one-pager, проверьте его и нажмите «Отправить на одобрение».
   > 2) Архив «Сессии Claude Code — <месяц>.zip» отправьте боту Hive @kg_export_bot (просто как файл,
   > без команды) — тогда отчёт появится и в Hive → Coding → «Мой отчёт». Если архивов несколько
   > («часть 1 из 2»), отправьте все. Telegram должен быть привязан к Hive: сайт → Coding → Telegram → `/link КОД`.
   Предложить поправить резюме, если пользователь хочет что-то добавить или убрать.

## Примечания

- Скрипт берёт **все проекты** на компьютере за месяц, не только текущую папку.
- Время — оценка по активности в Claude Code (паузы больше 30 минут не считаются). Это не
  учёт рабочего времени: часы в Hive берутся из трекера.
- `--name "Фамилия Имя"` добавит строку «Сотрудник» в шапку; `--out <путь>` — своё имя файла;
  `--dry-run` — только статистика без файла; `--no-zip` — не собирать архив сессий для бота.
- Архив содержит ужатые .jsonl сессий: без «размышлений» и длинных выводов инструментов, секреты
  вырезаны. Парсер Hive читает ровно то, что осталось. Части не больше 45 МБ (лимит бота 50).
- Работа вне Claude Code в файл не попадает — пользователь дописывает её в резюме сам.
- Claude Code удаляет транскрипты старше `cleanupPeriodDays` (по умолчанию 30 дней). Дни, чьи
  транскрипты уже стёрты, скрипт восстанавливает из `~/.claude/history.jsonl` (история запросов,
  не удаляется): проект, задачи и время есть, итогов и инструментов нет, в архив для бота такие
  сессии не входят; в отчёте они помечены «по истории запросов». Резюме по таким дням писать
  только по задачам, итоги не выдумывать. `install.sh` ставит `cleanupPeriodDays: 90`.
